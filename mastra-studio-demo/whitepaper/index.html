00 Executive summary · Snapshot 2026-07-24

The Regulatory-Intelligence Advantage

Why agents grounded in a curated regulatory dataset beat web search: on cost every day, and on correctness when it matters most.

This is a two-pronged argument. On the tail, a declined loan triggers a silent state obligation — a Colorado AI Act disclosure, a California Holden Act notice — that the applicant never asks about and the query never names. A memory-only baseline misses it. A frontier model with live web search misses it too. An agent grounded in a curated, jurisdiction-tagged regulatory index catches it. Getting regulatory guidance wrong or incomplete carries liability and reputation cost that dwarfs any savings on the query itself.

On the head — the everyday queries that make up the overwhelming majority of traffic — a Carver-grounded agent matches a frontier model running full web search on answer quality, while costing 43–63% less per 1,000 runs, independent of cache state, and more reproducible run to run.

You don't have to wait for a tail event to benefit — you're already overpaying on the head.

02 The cost of starting from scratch

This intelligence already exists — mined, structured, current

An agent reading these 244,297 documents cold, with no pre-extraction, would burn an estimated 732.9M tokens just to ingest them — before it answers a single question.

Every one of the 244,297 documents in the corpus has already been read, classified, and mined for obligations, citations, deadlines and penalties. A web-search agent starting from zero has none of that: it must locate primary sources, read them, and extract structure on every single run.

04 Correctness on the tail

The obligation nobody asked about

Three identical applicants, one identical declined automated loan — the state is the only variable, and it's supplied silently by the CRM lookup, never typed by the applicant.

A home-improvement loan is declined by an automated underwriting model. The support agent looks up the applicant in the CRM to draft the adverse-action explanation. The applicant's state is a field in that lookup — Colorado, California, or New York — never a word the applicant says. Both federal obligations apply everywhere:

Regulation B § 1002.9 — ECOA adverse-action notice FCRA § 615 — consumer-report adverse-action notice

But two of the three states silently add a further duty the moment the decision is automated. Colorado's AI Act (SB 24-205, amended by SB 26-189) requires a consumer notice after an AI/ADMT adverse decision. California's Holden Act (California Housing Financial Discrimination Act) requires a Fair Lending Notice with a statement of reasons. New York adds nothing beyond the federal baseline — it is the honest control.

Why this is dangerous, not just inconvenient

The failure is silent. Nothing in the query says "AI Act" or "Holden Act" — the obligation is triggered by an unstated combination of jurisdiction and decision method. A web-search agent that never suspects the obligation exists never searches for it, and returns a fluent, confident, complete-looking adverse-action letter that is quietly missing a legally required disclosure. The failure looks exactly like success. That gap is where liability and reputation risk live — not in queries that visibly fail.

05 The class this generalizes to

Silent-trigger queries, defined

The lending case is one instance of a general query class — and the corpus's jurisdiction tagging is what makes the win generalizable rather than a one-off trick.

Silent-trigger query: an actor attribute — jurisdiction, decision method, role — fires an unnamed obligation the user never mentions. Web search must first suspect the obligation exists in order to search for it, and fails at exactly that step, silently. A situation-queried obligation index returns the record because it is tagged to the situation, not to the words in the query.

06 Methodology & coverage roadmap

How this was measured, and what's next

Symmetric prompts, mechanical scoring, cache-adjusted costing, and an explicit floor on web's cost — plus an honest accounting of what's curated versus what's corpus-wide.

How it was measured

All three arms (baseline, web search, Carver) were run against the same model, openai/gpt-5.6-sol, with symmetric prompts and mechanical scoring — the same rubric applied to every arm's output, not a subjective read. Cost figures are cache-adjusted: fresh vs. cached input tokens are billed at their own published rates ($5/M fresh input, $0.50/M cached input, $30/M output, plus $0.01 per web-search call) and the web-search cost is reported as a range across cache states rather than a single number, because it moves and Carver's doesn't.

What's pinned, what's estimated

§3's cost and token figures are a real measurement taken on 2026-07-23. §2's ~732.9M source-read token figure is a stated estimate (3,000 tokens/doc × 244,297 docs), not a metered cost. §4/§5's tail-case win runs on 4 hand-curated records layered onto a 7,146-record realistic haystack — a demonstration of what jurisdiction-tagged coverage delivers, confirmed honest by its own ablation, not a claim that every US state carries this coverage today.

Coverage roadmap

The corpus already carries state-level tags for California (3,672 records), Texas (2,547), New York (2,368) and more (§1, §5) — real coverage, not curated for the demo. What's curated today are the specific Colorado AI Act and California Holden Act obligation records that made the CO/CA hits possible. The roadmap is to extend that same obligation-extraction pipeline (§1's structured-intelligence layer — already applied corpus-wide to produce 681,249 obligations and 711,026 resolved citations) to close the remaining state-AI-disclosure gap, so the tail-case win stops depending on 4 hand-picked records and starts depending on the same pipeline that already covers the rest of the corpus.
